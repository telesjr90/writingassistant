# ChatGPT and GitHub Project Memory Supervision Policy

This copy-ready policy governs Project Memory binding during application work.
It does not change ChatGPT settings and does not make generated evidence
authoritative.

## Copy-ready Project Instructions

1. A live GitHub repository or pull request at one exact full SHA, together
   with its deterministic Project Memory supervision handoff, may satisfy
   ordinary same-task application implementation binding.
2. Tracked repository files remain authoritative. GitHub checks, artifacts,
   step summaries, PR comments, local handoffs, and Project Source packages
   are generated evidence only.
3. An application-only commit under the same active, routed, dependency-
   eligible frontier task does not require a new mid-task 25-file Project
   Source rotation when supervision returns `READY` or
   `READY_WITH_ADVISORIES` with
   `project_memory_commit_lag_application_only`.
4. Commit-lag evidence must never call stale Project Memory `FRESH`. The
   advisory is valid only when the accepted package commit is an ancestor on
   the same branch and every intervening path is bounded application code or a
   directly related application test. Any control-plane path fails closed.
5. Closeout and governance remain exact-commit strict. They require clean
   tracked state, zero Plan Integrity blockers, passing validators and required
   tests, exact-commit `FRESH` Project Memory, and verified semantic,
   authority, render, quality, inventory, and checksum packages.
6. Local unpushed commits use the repository-owned local handoff from
   `scripts/project_memory/supervise.py`; no network or pushed branch is
   required. A branch push still requires explicit owner authorization.
7. A new branch, task, owner decision, routing-policy change, authority change,
   schema change, Project Instructions change, shared skill/agent change,
   workflow change, task/dependency/frontier change, or Project Memory protocol
   change requires a new strict baseline before implementation continues.
8. The 25-file Project Source package remains a fallback/bootstrap context
   mechanism and is still required when current policy calls for a new full
   authority baseline. It is not a commit-by-commit replication protocol.
9. Conflicting GitHub, local checkout, Project Source, continuation, routing,
   task, dependency, frontier, or Project Memory evidence fails closed. Use the
   tracked exact-SHA repository to diagnose the conflict; generated evidence
   never selects truth.
10. Nothing in a supervision handoff activates, completes, accepts, reorders,
    or mutates a task; advances a frontier; changes dependencies; promotes a
    candidate; applies a promotion; mutates approved Memory/Canon; or
    authorizes story-prose generation. Application task synchronization is a
    separate explicit closeout action.

The complete audit record is the checksum-verified workflow artifact or local
handoff package. The stable PR comment and status check are bounded navigation
surfaces only.
