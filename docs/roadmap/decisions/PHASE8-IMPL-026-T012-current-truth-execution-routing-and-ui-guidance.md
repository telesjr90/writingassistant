## Prompt and eligibility contract

Every implementation prompt must state near its beginning: task ID, resolved
execution class, model category, reasoning level, risk class, owner-only status,
concise rationale, escalation conditions, and authoritative routing source
locator. Prompt generation fails closed when routing is absent/conflicting,
scope or branch applicability is stale, a parent/child conflict lacks a valid
override, an owner-only task is delegated, a task is inactive or dependency-
ineligible, or historical routing is presented as current.

OpenCode work escalates to Codex for unresolved architecture, schema or
persistence changes, approved Memory/Canon or apply-promotion contact, difficult
real-runtime debugging, the same exact validation failing twice, insufficient
authorized scope, architecture replacement, provenance/evidence/candidate/
owner-control boundary changes, or possible false MVP/owner-acceptance claims.

## Shared Impeccable UI policy

Every task that audits, reviews, plans, designs, implements, tests, validates,
or closes frontend/UI/UX behavior must use
`.agents/skills/writing-assistant-ui-execution/SKILL.md`, which references the
installed `.agents/skills/impeccable/SKILL.md`. This applies to Codex, OpenCode
Go, owner-only UI decisions, and terminal UI validation.

The wrapper provides audit, implementation, and validation modes. It requires
current repository truth and routing resolution first; preserves T007B owner-
only selection; and fails closed on browser, mutation, asset generation,
dependency installation, or external-tool execution unless the active task
explicitly authorizes it. Impeccable output remains generated evidence. It
cannot expand scope, select a component library, create an owner decision,
authorize dependencies, change task status, establish application truth or
acceptance, or establish MVP readiness.

UI classification uses explicit routing capability tags, roadmap boundary
tags, allowed frontend path scope, and validation requirements before a title
fallback. A UI-related route without the shared wrapper is invalid.
